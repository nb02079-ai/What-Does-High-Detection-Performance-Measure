# Jacobs et al. (2022) — 벌거벗은 임금님: 네트워크 보안 모델을 결정트리로 비춰 보기

## 1. 한 줄 요약

블랙박스 모델에서 **충실도가 높고 단순한 결정트리**를 뽑아내는 도구 TRUSTEE로, 발표된 네트워크 보안 모델들이 **지름길·허위 상관·분포 밖 샘플에 대한 취약성**에 기대고 있음을 보인 논문이다.

## 2. 왜 이 논문을 읽나

**본 연구와 발상이 가장 가까운 선행 연구**다. 결정트리로 보안 모델의 지름길을 드러내고, 그 원인을 **데이터 수집 과정**에서 찾아낸다. 특히 이 논문이 분석한 CIC-IDS-2017은 CIC-MalMem-2022를 만든 **같은 연구소**(캐나다 사이버보안연구소)의 데이터셋이다.

## 3. 미리 알아둘 개념

| 개념 | 쉬운 설명 |
|---|---|
| **과소 명세(underspecification)** | 모델의 성공(높은 정확도)이 데이터의 본질적 구조를 배운 덕인지, 우연히 갖게 된 편향 덕인지 정해지지 않은 상태. 저자들은 이를 지름길·허위 상관·분포 밖 일반화 실패로 나눈다 |
| **충실도(fidelity)** | 뽑아낸 결정트리가 원래 블랙박스 모델의 판정을 얼마나 똑같이 따라 하는지. 분류에서는 블랙박스 판정과 트리 판정 사이의 F1으로 잰다. **정확도와 다르다** — 정답이 아니라 블랙박스를 맞히는 정도 |
| **전역 설명 vs 국소 설명** | 국소 설명(LIME, SHAP 등)은 샘플 하나의 판정을 설명한다. 전역 설명은 모델이 **전체적으로** 어떻게 판정하는지를 하나의 해석 가능한 모델로 보여준다 |
| **모방 학습** | 교사(블랙박스)의 판정을 학생(결정트리)이 따라 배우게 하는 방식 |
| **TTL** | IP 패킷이 거칠 수 있는 최대 홉 수. 운영체제마다 **초기값이 다르다**(리눅스 64, 윈도우 128 등) |

## 4. 방법 — TRUSTEE

### 4.1 네 가지 요구 조건
1. **모델과 무관** — 어떤 블랙박스에도 쓸 수 있어야 한다
2. **높은 충실도** — 블랙박스의 판정을 잘 따라 해야 한다
3. **낮은 복잡도** — 도메인 전문가가 읽을 수 있을 만큼 작아야 한다
4. **안정성** — 어떤 표본으로 뽑았느냐에 따라 결과가 크게 달라지지 않아야 한다

### 4.2 알고리즘
| 단계 | 내용 |
|---|---|
| 안쪽 반복 (N회) | 데이터의 일부(M)를 무작위로 뽑아 블랙박스의 판정을 정답 삼아 결정트리를 학습 → 트리가 틀린 샘플은 블랙박스에 다시 물어 데이터에 보탬 |
| 바깥 반복 (S회) | 안쪽 반복으로 만든 트리 중 **충실도가 가장 높은** 것을 고르고, **상위 k개 가지만 남기는 가지치기**(Top-k Pruning)로 단순화 |
| 최종 선택 | S개의 후보 트리 가운데 서로 판정이 가장 많이 일치하는(**평균 일치도가 가장 높은**) 트리를 출력 |
| 권장 시작값 | S=10, N=50, M=입력의 30%, k=10 |

### 4.3 신뢰 보고서 — 세 가지 편향 확인법
| 편향 | 확인 방법 |
|---|---|
| **지름길** | 트리를 보고, **특징 몇 개**만으로 데이터 대부분을 분류하는지 확인 |
| **허위 상관** | 가장 중요한 특징을 지우고 다시 학습 → 정확도가 그대로면 모델이 **다른 대체 특징**을 찾은 것 |
| **분포 밖 샘플** | 중요 특징의 값 분포를 보고, 실제 운영 환경의 분포와 맞는지 판단 → 현실적인 변형 데이터로 검증 |

⭐ **비대칭성**: 편향이 하나라도 **있으면** 그 모델을 믿을 수 없다는 증거가 된다. 그러나 편향이 **발견되지 않았다고** 믿을 수 있다는 뜻은 아니다.

⭐ **지름길에 대한 단서**:
> 특징 몇 개만으로 대부분을 정확히 분류한다면 지름길의 강한 징후일 때가 많다. **다만 특징이 적다는 것은 그 문제가 실제로 단순해서 머신러닝이 필요 없다는 뜻일 수도 있다.**

## 5. 사례 연구

### 5.1 VPN 탐지 — 바이트 위치가 어긋난 데이터
- 1D-CNN이 VPN과 비VPN을 거의 완벽하게(정밀도·재현율 99.9~100%) 구분한다고 보고된 모델
- TRUSTEE가 뽑은 트리는 **바이트 세 개**(49·43·47번)만으로 블랙박스의 판정을 **완벽히 재현**(F1 1.0)
- 원인: 비VPN 샘플에는 **항상 이더넷 헤더가 있고**, VPN 샘플의 약 90%에는 **없었다**. 그래서 같은 위치의 바이트가 두 클래스에서 **전혀 다른 의미**를 가졌다 — 49번 바이트는 VPN에서는 IP 프로토콜 필드, 비VPN에서는 이더넷 주소의 일부
- 검증: 세 바이트만 바꿔도 정확도는 그대로였다 — 모델이 **다른 지름길**을 찾았기 때문. 앞쪽 128바이트를 무작위로 바꾸자 성능이 **동전 던지기 수준**으로 떨어졌다(평균 F1 0.955 → 0.398)

### 5.2 하트블리드 탐지 (CIC-IDS-2017) — 분포 밖 샘플에 무너짐
- 랜덤 포레스트가 하트블리드 공격 샘플을 **특징 하나**(서버 응답 패킷의 최대 길이)로 전부 분류
- 시험 분할에서 하트블리드 샘플은 **3개**, DDoS는 68만 개 — 극심한 불균형
- 원인: 데이터셋에서 하트블리드 공격의 **TCP 연결이 끝까지 닫히지 않아** 특정 특징 값이 극단적으로 커졌다
- 검증: 같은 도구로 **연결을 닫는** 현실적인 하트블리드 공격 1,000개를 새로 만들자 **하나도 탐지하지 못했다**(F1 0)

### 5.3 침입 탐지 nPrintML (CIC-IDS-2017) — ⭐ 수집 설정의 흔적
- 비트 단위로 패킷을 표현해 4,480개 특징을 쓰는 모델(F1 0.999)
- 트리의 상위 분기가 **IP TTL 필드의 비트**로 정상과 공격을 갈랐다
- 원인을 데이터셋 생성 설정에서 찾았다:
  - 공격은 **네트워크 바깥** 호스트에서, 정상은 **안쪽** 호스트에서 생성
  - 대부분의 공격은 **Kali Linux**(초기 TTL 64), DDoS는 **Windows 8.1**(초기 TTL 128) 호스트에서 생성
- TTL을 비롯한 중요 특징을 하나씩 지워도, TCP 옵션 비트만 남겼을 때조차 F1 0.990 — 고차원 특징 공간에서 **허위 상관을 계속 찾아냄**
- 검증: UCSB 캠퍼스 네트워크의 실제 트래픽에서 평균 F1 **0.282**, DoS는 **하나도** 탐지하지 못함

### 5.4 이상 탐지 Kitsune (Mirai) — 트래픽 양에만 기댐
- 115개 통계 특징을 쓰는 오토인코더 앙상블
- 트리를 보니 **시간당 패킷 양**만으로 이상을 판정. 합성 데이터의 공격 트래픽이 정상보다 약 6배 많았기 때문
- Arp et al.(2022)도 이 사례에서 간단한 상자 그림 방법이 비슷한 성능을 낸다고 보였다
- 검증: 공격 패킷의 간격을 벌려 양을 줄이자 탐지하지 못했다

| 사례 | 데이터 | 충실도 | 찾아낸 편향 |
|---|---|---|---|
| VPN 탐지 | ISCX VPN-nonVPN | 1.00 | 지름길 |
| 하트블리드 | CIC-IDS-2017 | 0.99 | 분포 밖 샘플 |
| 침입 탐지 | CIC-IDS-2017 | 0.99 | 허위 상관 |
| Mirai 이상 탐지 | Kitsune Mirai | 0.99 | 분포 밖 샘플 |

## 6. 본 연구에 적용하기

| Jacobs et al. | 본 연구 |
|---|---|
| 학습된 **모델**에서 결정트리를 **추출** | **데이터**에 얕은 결정트리를 **직접 맞춤** — 어떤 모델이든 쓸 수 있는 신호가 데이터에 있는지 봄 |
| 바이트 세 개로 CNN을 완벽히 재현 | 분기 하나(서비스 수)로 99.65% |
| CIC-IDS-2017의 TTL — **공격과 정상을 다른 호스트·다른 운영체제에서 생성**한 수집 설정의 흔적 | CIC-MalMem의 서비스 수 — 같은 연구소의 데이터셋에서 **수집 절차의 흔적일 가능성**. 단 같은 가상 머신에서 수집되었으므로 원인은 다를 수 있음 |
| "특징이 적은 것은 지름길일 수도, **문제가 단순한 것**일 수도" | 본 연구가 행위 해석과 구성 차이 해석을 **모두 열어 두는** 입장과 같음 |
| **현실적인 변형 데이터**로 검증(연결 닫기, 바이트 변형, 캠퍼스 트래픽) | 본 연구는 하지 못함 → 6장 한계와 향후 과제 |
| 중요 특징을 지우고 재학습해 대체 특징을 찾는지 확인 | DMBD에서 연도 정보를 지우는 대신 **평가 데이터를 재구성**해 기여를 분리 |
| 편향이 **없다는 것**은 신뢰의 증거가 아님 | 본 연구의 멤버십 추론 결과("검출되지 않음 ≠ 보장")와 같은 논리 |

### 주의
- 저자들 스스로 **재현 가능한 소수의 사례**만 분석했으므로 이 분야 전체를 대표하지 않는다고 밝혔다
- 이 논문이 다루는 것은 **네트워크 트래픽**이다. 호스트 메모리·행위 데이터에 같은 결론을 그대로 옮기면 안 된다
- 같은 연구소의 데이터셋이라는 사실만으로 CIC-MalMem에도 같은 문제가 있다고 말할 수 없다. **수집 설계에서 생긴 흔적을 의심해 볼 근거**가 될 뿐이다

### ⚠️ 본 연구가 저지른 실수 — 내용 오귀속
- 처음에는 이 논문의 내용을 "암호화 트래픽 분류기 대다수가 오래된 데이터셋 때문에 실제로는 비암호화 트래픽을 썼다"로 기록했다. 검색 결과에 여러 문헌이 섞인 것을 잘못 묶은 것이다
- 이 논문의 VPN 사례도 암호화 트래픽 데이터셋의 문제를 다루지만, 그 내용은 **이더넷 헤더 유무로 바이트 위치가 어긋난 것**이다. 비슷해 보이는 두 주장을 섞지 않도록 주의

## 8. 스스로 점검하기

**Q1.** "충실도"와 "정확도"는 어떻게 다른가?
<details><summary>답</summary>정확도는 정답을 얼마나 맞히는지, 충실도는 원래 블랙박스 모델의 판정을 얼마나 똑같이 따라 하는지다. TRUSTEE는 블랙박스를 설명하려는 것이므로 충실도를 목표로 한다.</details>

**Q2.** VPN 사례에서 세 바이트만 바꿨을 때 정확도가 떨어지지 않은 이유는?
<details><summary>답</summary>이더넷 헤더 유무로 바이트 위치가 어긋난 문제가 앞쪽 바이트 전반에 있어서, 모델이 다른 바이트에서 대체 지름길을 찾았기 때문이다. 앞쪽 128바이트를 통째로 바꾸자 동전 던지기 수준으로 떨어졌다.</details>

**Q3.** CIC-IDS-2017의 TTL 사례가 본 연구에 주는 시사점과 그 한계는?
<details><summary>답</summary>같은 연구소의 데이터셋에서 공격과 정상을 다른 호스트·운영체제로 생성한 수집 설정이 흔적을 남긴 선례다. CIC-MalMem의 서비스 수도 수집 절차의 흔적일 수 있다고 의심해 볼 근거가 된다. 그러나 CIC-MalMem은 같은 가상 머신에서 수집되었으므로 원인이 같다고 말할 수는 없다.</details>

**Q4.** "편향이 발견되지 않았다"는 결과를 어떻게 해석해야 하는가?
<details><summary>답</summary>모델을 믿을 수 있다는 증거가 아니다. 편향이 있으면 믿을 수 없다는 증거가 되지만, 없다는 것을 증명하기는 어렵다. 본 연구의 "멤버십 추론 공격으로 검출되지 않음 ≠ 프라이버시 보장"과 같은 논리다.</details>

**Q5.** 저자들은 특징이 적다는 것을 언제나 지름길의 증거로 보았는가?
<details><summary>답</summary>아니다. 지름길의 강한 징후일 때가 많지만, 문제 자체가 단순해서 머신러닝이 필요 없다는 뜻일 수도 있다고 단서를 달았다.</details>
