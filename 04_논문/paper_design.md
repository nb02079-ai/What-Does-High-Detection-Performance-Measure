## 1. 확정된 큰 틀

### 논문 제목 ✅ 확정

> **높은 탐지 성능은 무엇을 측정하는가**
> **— 호스트 행위 기반 악성코드 탐지 평가의 네 층위 분석**
>
> *What Does High Detection Performance Measure?*
> *A Four-Layer Analysis of Host-Behavior Malware Detection Evaluation*

**프로젝트 이름**: 탐지 성능 측정 연구 (*What Detection Performance Measures*)

**결정 경위**
- 이전 이름 "Device background AI security performance optimization"은 폐기 — 특히 **"optimization"이 논문 주장과 정반대**(단일 지표 최적화 관행을 비판하는 논문)
- 질문형(ⓑ) 채택: 서론 ¶2의 발견(99.65%)과 곧바로 이어지고 네 층위 구조를 담음
- **"탐지율" → "탐지 성능"으로 수정**: 본문에서 탐지율은 재현율(recall)을 뜻하나, 제목이 가리키는 발견은 정확도(4.1)·MCC(4.2)·재현율(4.4)에 걸쳐 있음. "탐지율"로 두면 서론 핵심 수치(정확도 99.65%)와 어긋나고 용어 일관성이 깨짐
- **부제에 "호스트 행위 기반" 명시**: 2장에서 네트워크 트래픽 연구(BiasSeeker 등)와 선을 그었으므로 영역을 제목에서 밝힘
- "Beyond Accuracy"류 표현은 회피 (Ribeiro et al., ACL 2020 CheckList 이후 진부)
- 프로토콜 v3.5의 "연구 주제"는 변경하지 않음 — 실험 기록과 논문 제시 방식은 별개

| 항목 | 결정 |
|---|---|
| 중심 주장 | **단일 지표 평가가 무엇을 놓치는가** (통합 프레이밍 ⓒ) |
| 분량 | 제한 없음, 완성도 우선 (본문 작성 중 재확인: 분량 신경 쓰지 않음) |
| 결과 구성 | **주장의 층위대로**: 벤치마크 → 모델 → 개선 → 해석 |
| 작성 순서 | 4장 그림·표 설계 → 3장 → 1·2장 → 5~7장 |
| 해석 정정 경위(4.4) | 결과에 두는 것으로 **잠정**. 4.4 작성 시 재논의 |

### 원칙
- **그림 하나에 메시지 하나** — 독자가 3초 안에 알아챌 한 가지
- 공식 판정(사전등록 규칙)과 사후 해석을 **명확히 구분**
- 수치 범위(전체 데이터 vs Train+Val) 혼용 금지

## 2B. 1장 서론 ✅ 설계 확정

**문단 구성**
```
¶1 맥락     ML 탐지 확산, 성능은 주로 단일 탐지 지표로 보고됨 (2~3문장)
¶2 발견     CIC-MalMem: 원 논문 99%, 후속 99.9~99.99% → 깊이 1 트리 99.65%
¶3 확장     한 데이터셋의 문제가 아니다. 탐지 성능은 다른 축도, 해석도 보장하지 않는다
¶4 차별화   Arp et al.의 체계화 → 본 연구는 무엇을 더하나 (명시적)
¶5 접근     연구 질문, DMBD, 4축 진단, 사전 명세, 봉인된 평가셋
¶6 기여     4개 층위 (글머리표 목록)
¶7 구성     논문 로드맵
```

**기여 진술 (4개 층위로 확정, 방법론적 기여는 별도 항목으로 두지 않음)**
1. 벤치마크 층위 — 두 공개 벤치마크가 각각 다른 방식으로 평가를 왜곡함을 보이고 크기를 정량화
2. 모델 층위 — 4축 동시 평가로 구조 차이가 튜닝 차이를 압도함을 보임
3. 개선 층위 — 사전 명세된 비열등성 검정으로 선택적·일괄 개선 중 어느 쪽도 지배하지 않음을 보임 (**부정적 결과를 기여로 명시**)
4. 해석 층위 — 탐지율 기반 해석의 모델 간 차이 대부분이 판단 경계에서 옴을 보임 (탐지율 폭 ≈ AUC 폭 × 8)

**주장하지 않는 것**: 새 프레임워크 제안 / 선택적 개선의 효과 / 일반화 / 선행 연구 반박 / "증명"

**Arp et al. 차별화 (서론 ¶4에서 명시)** — ⚠️ 2026-10-01 원문 대조 후 수정

~~"Arp는 30편 조사로 함정을 **분류**, 본 연구는 **정량화**"~~ → **틀림.** Arp et al.도 실증 분석으로 개별 함정이 비현실적인 성능과 해석으로 이어짐을 보였음(공식 사이트, 안드로이드 악성코드 사례에서 P1·P4·P7의 영향 제시)

| Arp et al. (2022) | 본 연구 |
|---|---|
| 함정 열 가지를 체계화하고 **개별 함정을 따로** 실증 | 단일 지표 평가가 **네 층위에서 차례로** 무엇을 놓치는지 **한 연구 안에서** 추적 — 층위 사이의 연결(연도 교란 → 시간적 일반화 해석, 개선의 경계 이동 → 탐지율 향상처럼 보임) |
| 위협 모델·실험실 평가 함정에서 **멤버십 추론·실행 비용을 고려하라고 권고** (2026-10-01 원문 확인) | 그 권고 대상인 프라이버시·자원 비용을 탐지·강건성과 **같은 모델 집합에서 실제로 측정** |
| — | **개선 전략의 비교**(선택적 vs 일괄) |
| — | 분석을 사전 명세하고 평가 집합을 봉인한 설계에서도 **해석 단계의 함정이 남음** |

**⚠️ 쓰지 않는 표현**: "처음", "최초", "유일", "드물다" — Arp를 인용한 다른 논문도 "그들의 함정을 구체적으로 구현한다"는 포지셔닝을 씀(5단계 검색에서 확인)

**¶2 확정 초안 (톤 기준점)**
> 이러한 평가 관행의 한계는 CIC-MalMem-2022에서 선명하게 드러난다. 이 데이터셋은 메모리 기반 난독화 악성코드 탐지를 위해 구축되었으며, 원 논문은 스태킹 앙상블로 99%의 정확도를 보고했다[Carrier]. 이후 연구들은 경량 모델, 부스팅, 교차 어텐션 구조 등을 적용해 이 수치를 99.9~99.99%까지 끌어올렸다[Dener; Sensors; …]. 그러나 본 연구가 이 데이터셋에 깊이 1의 결정트리를 적용한 결과, 단 하나의 분기만으로 99.65%의 정확도에 도달했다. 분기에 쓰인 특징은 실행 중인 서비스 수였으며, 정상 샘플은 대부분 395개, 악성 샘플은 대부분 389개의 값을 가졌다. 행동이 전혀 다른 15개 악성코드 계열이 모두 같은 값을 보였다는 점에서, 이 여섯 개의 차이는 악성 행위의 흔적이라기보다 악성 샘플을 실행할 때의 시스템 구성 차이일 가능성이 높다. 이 결과는 높은 정확도가 무엇을 측정하고 있는지 되묻게 한다.

**각 절의 "빈틈" (수정 반영)**

| 절 | 기존 연구 | 본 연구가 채우는 것 |
|---|---|---|
| 2.2 | 지름길 학습(Geirhos, Lapuschkin). **네트워크 분야에서 지름길 진단 연구가 진행됨** — Jacobs et al.(모델에서 결정트리 추출), BiasSeeker(입력 특징의 지름길 탐지 + **특징 가림으로 성능 영향 측정**, 악성 트래픽 포함). CIC-MalMem으로 99.9%대 보고 다수 | 이 문제의식을 **호스트 행위·메모리 기반 악성코드 탐지**로 확장. **입력에 없는 교란 변수**(수집 연도)는 특징 가림으로 다룰 수 없어 **평가 데이터 재구성**으로 기여를 분리 |
| 2.3 | MIA(Shokri, Carlini)·강건성(Pierazzi)·자원이 **각각 따로** 연구됨 | 네 축을 **한 모델 집합에 동시 적용** |
| 2.4 | 스태킹·튜닝으로 탐지 성능 향상. 앙상블 이득 한계(Caruana), 다양성-성능 무관(Kuncheva) | 개선이 **다른 축에 미치는 영향**을 사전 명세된 검정으로 비교 |
| 2.5 | 시간적 평가 편향(TESSERACT), MCC 근거(Chicco) | 탐지율 기반 시간 격차에서 **보정과 구분 능력이 섞이는 문제** |

**한정어 원칙**: "~는 드물다"가 아니라 "본 연구가 확인한 범위에서는~"으로 서술. 체계적 문헌 조사를 수행하지 않았으므로.

**2.2의 이론적 닻**
- Lapuschkin et al.: "표준 성능 평가 지표는 다양한 문제 해결 방식을 구분하지 못할 수 있다" → 중심 주장과 직결, **서론 ¶3에도 활용 가능**
- Geirhos et al.: 지름길의 정의 — 단, **전이 실패를 시험하지 않았으므로 "지름길일 가능성이 높다"로만**

## 2D. 5~7장 ✅ 설계 확정

### 5장 논의 — 결과를 반복하지 않고 층위를 가로질러 종합

```
5.1 네 층위의 공통 메커니즘
5.2 사전 명세는 무엇을 막았고, 무엇을 못 막았나
5.3 실무적 함의
```

**5.1 공통 메커니즘**: "요약 수치는 서로 다른 원인을 같은 숫자로 압축한다" — Lapuschkin et al.과 연결

| 층위 | 하나의 수치가 | 가린 것 |
|---|---|---|
| 벤치마크 | 정확도 99.65% | 자명한 규칙 하나로 설명된다는 사실 |
| 모델 | 탐지 MCC | 프라이버시·강건성·자원의 차이 |
| 개선 | "개선되었다" | 축 사이의 트레이드오프 |
| 해석 | 탐지율 | 보정과 구분 능력의 구분 |

**5.2 사전 명세 성찰 (두 열 모두 포함)**

| 막은 것 | 못 막은 것 |
|---|---|
| Test 오염 (H5-Test 봉인·해시) | 명세 자체의 오류 (§10.1 크기→유의성 치환) |
| 결과 기반 데이터셋 선택 | 설계 결함 (교란학습 클래스 비율 이동) |
| 불리한 규칙의 번복 (H2 n=9→7에도 유지) | 가설 프레이밍 문제 (H5 부작용축 정의) |
| 판정 번복 (H5 설계 문제 발견 후에도 기각 유지) | 해석 오류 (B·일괄, 추가 진단으로 정정) |

→ 결론: **사전 명세는 "결과를 보고 고르는 것"은 막지만 "처음부터 잘못 정한 것"은 막지 못한다.** 명세 오류 대부분은 결과를 보고서야 발견되었다.
- **H5 사후 해석을 이 절에 배치**: "선택적 개선이 문제없는 축에 개입하지 않아 탐지를 보존했다" — **"사후 해석"임을 명시**, 판정 근거로 쓰지 않음

**5.3 실무적 함의**
- 공개 벤치마크 사용 전 깊이 1 트리 같은 자명한 기준선 확인 (비용 거의 0)
- 시간적 평가에 임계값 비의존 지표 병기
- 기본 설정 RF가 진단 3축 모두 최하위 — 기본값 그대로 쓰는 관행 재고
- 자원: 업계 부하 기준 네 모델 모두 CPU 1% 미만, 집계 비용이 하한 (§7.1 탐색적 분석, 직렬화 크기 A 110MB 등도 여기서)

### 6장 한계 — 결론별 신뢰성 표 + 범주별 목록 (향후 과제와 짝)

**6.1 결론별 신뢰성**

> ⚠️ **작성 시 첫머리에 정의 문장을 둔다**: "여기서 신뢰성은 통계적 신뢰구간과 별개로, 결론이 연구의 한계에 흔들리지 않는 정도를 뜻한다." — 본문에 "신뢰구간"이 매우 많이 나오므로 혼동 방지

| 주요 결론 | 신뢰성 | 흔드는 한계 |
|---|---|---|
| CIC-MalMem 환경 지문 (99.65%) | 높음 | 전이 실패 미시험 |
| DMBD 연도 교란의 존재·크기 | 높음 | 잔여 기여 약 0.03 MCC |
| 구조 차이 > 튜닝 차이 (H3) | 높음 | 단일 데이터셋 |
| 스태킹 효과 | 판정 유보 | 검정력 (Val 8,000) |
| H1 반례 | 낮음 | 차이 0.0029, CI 중첩 |
| H2 양의 경향 | 낮음 | n=7, net_connect 예외 |
| H5 기각 | 높음 | 부작용축 정의 문제 |
| 선택적 개선이 설계대로 작동 | 높음 | — |
| 탐지율 ≠ 구분 능력 (8배) | 높음 | 단일 데이터셋, 2024 코호트 |

**6.2 범주별 한계 → 향후 과제**

*데이터·일반화*
| 한계 | 향후 과제 |
|---|---|
| 단일 데이터셋, 교차 검증 미수행 (H4 폐기) | 수집 환경이 다른 호스트 행위 벤치마크에서 재현 |
| 연도 교란 잔여 기여 | 연도 균형 재수집 또는 연도 층화 평가 |
| family 라벨 부재 → 미지 family 평가 불가 | family 라벨이 있는 데이터셋 |
| 저활동 잠복형 악성코드는 관측 범위 밖 (§1A.3) | 장기 관측 창 데이터 |

*측정*
| 한계 | 향후 과제 |
|---|---|
| 특징 공간 교란 ≠ 실제 회피 | 문제 공간 공격 (Pierazzi et al.) |
| 비례 감소만 시험 → net_connect 역설 | 모방(mimicry) 교란 |
| H2 n=7 | 특징이 많은 데이터셋 |
| MIA TPR@1%FPR 낮음 | 더 강한 공격 (LiRA 등) |
| 자원: 단일 코어, 경합·실제 수집 비용 미측정, 1ms 기준의 자의성·측정 분산 취약 | 실제 에이전트 환경 측정 |
| 지름길 전이 실패 미시험 | 다른 수집 환경으로 규칙 전이 시험 |

*설계*
| 한계 | 향후 과제 |
|---|---|
| **`duration_s`를 현실성 낮은 감소 방향으로 교란** (3장 작성 중 발견) | 특징별 현실적 조작 방향(증가/감소)을 분리해 교란 |
| **H3·H5 신뢰구간에 다중비교 보정 미적용** (BH는 H2에만) | 신뢰구간 수준의 동시 보정(예: Bonferroni 조정 신뢰수준) |
| H5 부작용축 정의 | "두 경로 모두 개입하지 않는 축"으로 한정 |
| 교란학습 클래스 비율 이동 | 정상 샘플 동비율 증강 또는 클래스 가중 보정 |
| 스태킹 베이스 다양성 낮음 | 이종 알고리즘 베이스 |
| 비용 민감 평가 미수행 (§1A.4) | 조직별 오분류 비용 반영 |

**⭐ 4.1 v1에서 이관된 H4 문단 (6장 데이터·일반화 항목에 사용)**
> 이 교란은 본 연구의 설계에도 영향을 주었다. 본 연구는 당초 2017년 코호트와 2024년 코호트 사이에서 취약성 패턴이 재현되는지를 검정할 계획이었다(H4). 그러나 DMBD 2025는 2024년 악성 샘플 2,367개를 모두 공식 시험 분할에 배치했기 때문에, 모델 학습에 쓸 수 있는 학습·검증 데이터(32,000개)의 2024년 샘플 5,623개는 전부 정상이었다. 그림 2의 2024년 악성 비율 16.2%는 전체 데이터 기준이며, 학습·검증 데이터로 한정하면 0%가 된다. 단일 클래스로는 분류 자체가 성립하지 않으므로 H4는 폐기되었다. 다른 연도 조합도 검토했으나, 2017년 코호트는 정상 샘플이 1,000개뿐이어서 클래스를 균형 있게 맞추면 2,000개로 줄어들고, 이는 멤버십 추론 진단에 필요한 검정력을 확보하기에 부족했다.

## 2A. 3장 연구 설계 ✅ 확정

**원칙**: 4장의 결과를 이해·재현하는 데 필요한 것만 3장에, 나머지는 부록.

**목차**
```
3.1 연구 질문과 가설
3.2 사전 명세와 변경 관리
3.3 데이터 (DMBD 주실험, CIC-MalMem 사례연구, 특징 12개)

3.5 모델
3.6 진단 축과 측정

```

**⚠️ 표현 원칙 — "사전등록" 사용 금지**
- 사전등록(preregistration)은 OSF·AsPredicted 등 **공개 저장소에 타임스탬프로 등록**해 제3자가 검증 가능한 것을 뜻함
- 본 연구의 프로토콜은 **내부 문서** → 결정 시점을 외부에서 검증 불가
- 논문에서는 **"사전 명세(pre-specified protocol)"**로 표현하고, "실험 착수 전 분석 계획을 문서화하고 모든 변경을 사유와 함께 기록했다"로 서술
- **공개 등록이 아님을 한계로 명시**하고, 변경이력 전문을 부록 A로 공개

**연구 과정 변화의 3단 처리 기준**

| 성격 | 처리 | 예시 |

| 그 자체가 **결과** | 4장에서 다루고 3장은 참조만 | CIC-MalMem 교체(→4.1), H4 폐기(→4.1) |

| **절차적** | 부록 A에만 | F1→MCC, TPE→GP-EI, HistGB 대체 |
