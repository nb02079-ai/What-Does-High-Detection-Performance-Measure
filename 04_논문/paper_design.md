## 1. 확정된 큰 틀

### 논문 제목 ✅ 확정

> **높은 탐지 성능은 무엇을 측정하는가**
> **— 호스트 행위 기반 악성코드 탐지 평가의 네 층위 분석**
>
> *What Does High Detection Performance Measure?*
> *A Four-Layer Analysis of Host-Behavior Malware Detection Evaluation*

**프로젝트 이름**: 탐지 성능 측정 연구 (*What Detection Performance Measures*)

**결정 경위**
- 이전 이름 "Device background AI security performance optimization"은 폐기 — 특히 **"optimization"이 논문 주장과 정반대**(단일 지표 최적화 관행을 비판하는 논문)
- 질문형(ⓑ) 채택: 서론 ¶2의 발견(99.65%)과 곧바로 이어지고 네 층위 구조를 담음
- **"탐지율" → "탐지 성능"으로 수정**: 본문에서 탐지율은 재현율(recall)을 뜻하나, 제목이 가리키는 발견은 정확도(4.1)·MCC(4.2)·재현율(4.4)에 걸쳐 있음. "탐지율"로 두면 서론 핵심 수치(정확도 99.65%)와 어긋나고 용어 일관성이 깨짐
- **부제에 "호스트 행위 기반" 명시**: 2장에서 네트워크 트래픽 연구(BiasSeeker 등)와 선을 그었으므로 영역을 제목에서 밝힘
- "Beyond Accuracy"류 표현은 회피 (Ribeiro et al., ACL 2020 CheckList 이후 진부)
- 프로토콜 v3.5의 "연구 주제"는 변경하지 않음 — 실험 기록과 논문 제시 방식은 별개

| 항목 | 결정 |
|---|---|
| 중심 주장 | **단일 지표 평가가 무엇을 놓치는가** (통합 프레이밍 ⓒ) |
| 분량 | 제한 없음, 완성도 우선 (본문 작성 중 재확인: 분량 신경 쓰지 않음) |
| 결과 구성 | **주장의 층위대로**: 벤치마크 → 모델 → 개선 → 해석 |
| 작성 순서 | 4장 그림·표 설계 → 3장 → 1·2장 → 5~7장 |
| 해석 정정 경위(4.4) | 결과에 두는 것으로 **잠정**. 4.4 작성 시 재논의 |

### 원칙
- **그림 하나에 메시지 하나** — 독자가 3초 안에 알아챌 한 가지
- 공식 판정(사전등록 규칙)과 사후 해석을 **명확히 구분**

## 2B. 1장 서론 ✅ 설계 확정

**문단 구성**
```
¶1 맥락     ML 탐지 확산, 성능은 주로 단일 탐지 지표로 보고됨 (2~3문장)
¶2 발견     CIC-MalMem: 원 논문 99%, 후속 99.9~99.99% → 깊이 1 트리 99.65%
¶3 확장     한 데이터셋의 문제가 아니다. 탐지 성능은 다른 축도, 해석도 보장하지 않는다
¶4 차별화   Arp et al.의 체계화 → 본 연구는 무엇을 더하나 (명시적)
¶5 접근     연구 질문, DMBD, 4축 진단, 사전 명세, 봉인된 평가셋
¶6 기여     4개 층위 (글머리표 목록)
¶7 구성     논문 로드맵
```

**기여 진술 (4개 층위로 확정, 방법론적 기여는 별도 항목으로 두지 않음)**
1. 벤치마크 층위 — 두 공개 벤치마크가 각각 다른 방식으로 평가를 왜곡함을 보이고 크기를 정량화
2. 모델 층위 — 4축 동시 평가로 구조 차이가 튜닝 차이를 압도함을 보임
3. 개선 층위 — 사전 명세된 비열등성 검정으로 선택적·일괄 개선 중 어느 쪽도 지배하지 않음을 보임 (**부정적 결과를 기여로 명시**)
4. 해석 층위 — 탐지율 기반 해석의 모델 간 차이 대부분이 판단 경계에서 옴을 보임 (탐지율 폭 ≈ AUC 폭 × 8)

**주장하지 않는 것**: 새 프레임워크 제안 / 선택적 개선의 효과 / 일반화 / 선행 연구 반박 / "증명"

**Arp et al. 차별화 (서론 ¶4에서 명시)** — ⚠️ 2026-10-01 원문 대조 후 수정

~~"Arp는 30편 조사로 함정을 **분류**, 본 연구는 **정량화**"~~ → **틀림.** Arp et al.도 실증 분석으로 개별 함정이 비현실적인 성능과 해석으로 이어짐을 보였음(공식 사이트, 안드로이드 악성코드 사례에서 P1·P4·P7의 영향 제시)

| Arp et al. (2022) | 본 연구 |
|---|---|
| 함정 열 가지를 체계화하고 **개별 함정을 따로** 실증 | 단일 지표 평가가 **네 층위에서 차례로** 무엇을 놓치는지 **한 연구 안에서** 추적 — 층위 사이의 연결(연도 교란 → 시간적 일반화 해석, 개선의 경계 이동 → 탐지율 향상처럼 보임) |
| 위협 모델·실험실 평가 함정에서 **멤버십 추론·실행 비용을 고려하라고 권고** (2026-10-01 원문 확인) | 그 권고 대상인 프라이버시·자원 비용을 탐지·강건성과 **같은 모델 집합에서 실제로 측정** |
| — | **개선 전략의 비교**(선택적 vs 일괄) |
| — | 분석을 사전 명세하고 평가 집합을 봉인한 설계에서도 **해석 단계의 함정이 남음** |

**⚠️ 쓰지 않는 표현**: "처음", "최초", "유일", "드물다" — Arp를 인용한 다른 논문도 "그들의 함정을 구체적으로 구현한다"는 포지셔닝을 씀(5단계 검색에서 확인)

**¶2 확정 초안 (톤 기준점)**
> 이러한 평가 관행의 한계는 CIC-MalMem-2022에서 선명하게 드러난다. 이 데이터셋은 메모리 기반 난독화 악성코드 탐지를 위해 구축되었으며, 원 논문은 스태킹 앙상블로 99%의 정확도를 보고했다[Carrier]. 이후 연구들은 경량 모델, 부스팅, 교차 어텐션 구조 등을 적용해 이 수치를 99.9~99.99%까지 끌어올렸다[Dener; Sensors; …]. 그러나 본 연구가 이 데이터셋에 깊이 1의 결정트리를 적용한 결과, 단 하나의 분기만으로 99.65%의 정확도에 도달했다. 분기에 쓰인 특징은 실행 중인 서비스 수였으며, 정상 샘플은 대부분 395개, 악성 샘플은 대부분 389개의 값을 가졌다. 행동이 전혀 다른 15개 악성코드 계열이 모두 같은 값을 보였다는 점에서, 이 여섯 개의 차이는 악성 행위의 흔적이라기보다 악성 샘플을 실행할 때의 시스템 구성 차이일 가능성이 높다. 이 결과는 높은 정확도가 무엇을 측정하고 있는지 되묻게 한다.
> ⚠️ **2026-09-29 수정**: "두 수집 환경" → 데이터셋 README상 **같은 VM**이므로 "실행 시 시스템 구성 차이"로 정정, 계열 균일성 근거 추가

## 0A. 재발 방지 체크리스트 ⭐ (2026-10-01 — 원고를 쓰거나 고칠 때마다 확인)

1~4장 초안과 인용 확인 과정에서 실제로 저지른 실수에서 뽑은 기준이다. 괄호 안은 해당 사례.

### A. 인용
1. **서지만 확인하고 끝내지 않는다.** 원고에 쓰는 주장 하나하나를 원문(최소 초록, 가능하면 본문)과 대조한다 (Caruana·Kuncheva·Carlini 오독)
2. **2차 인용·검색 결과 조각·프로토콜 메모에서 옮기지 않는다.** 다른 논문이 요약한 수치, 여러 문헌이 섞인 스니펫, 설계 단계의 메모는 원문으로 재확인 (Dener 99.9→99.97, Jacobs 오귀속, "스태킹 앙상블")
3. **우리 결과를 설명하기 좋은 방향의 인용일수록 더 의심한다.** 오독 세 편이 모두 그 방향이었음
4. **저자의 결론과 단서 문장을 구분한다.** 과장을 경계하는 문장을 결론처럼 옮기지 않는다 (Caruana "2.5배")
5. **두 문헌을 한 문장에 묶을 때 방법이 섞이지 않게 한다** (Jacobs·Wang을 "둘 다 특징을 가린다"로 묶은 오류)
6. **분야 전체에 대한 주장은 쓰지 않거나 확인 범위로 한정한다** — "처음·유일·드물다·주로·대개" (2.2 초안)
7. **같은 논문 안에서도 수치가 다를 수 있다.** 결과를 보고한 절의 값을 쓴다 (Shafin 99.96 vs 99.98)

### B. 수치
8. **모든 수치는 데이터·산출물에서 다시 뽑는다.** 기억·설계 문서·실험 보고서에서 옮기지 않는다 (교차검증 분할 방식, 구 분할 과적합 격차)
9. **수치의 범위를 실제 사용한 데이터와 맞춘다** — 어느 분할, 어느 시드, 어느 집합 기준인지 (학습·검증 32,000 vs 학습 24,000)
10. **측정하지 않은 것을 사실처럼 쓰지 않는다.** 나중에 측정했다면 사전 명세에 없던 **사후 분석**임을 밝힌다 (기반 모델 예측 상관)
11. **유리한 지표만 고르지 않는다.** 관련 지표를 모두 제시한다 (선택적 개선을 MCC·flip 두 축만으로 "거의 불변"이라 함)
11-1. **반올림된 값을 다시 반올림하지 않는다.** 표시 자릿수를 바꿀 때는 원래 값(분자·분모)에서 다시 계산한다 (중복 배수 4,800÷575=8.3478을, 이미 반올림된 8.35에서 다시 반올림해 "약 8.4"로 씀 — 퇴고 4단계에서 발견)

### C. 해석·논리
12. **약한 도구로 "못 찾았다"를 "없다"로 읽지 않는다** (단순한 멤버십 추론의 낮은 참양성률 → "실용적 위협 아님")
13. **해석을 추가·변경하면 그 해석이 닿는 모든 곳을 다시 읽는다** — 같은 절의 다른 문단, 서론, 관련 연구, README (Madamidola 추가 → 4.1 둘째 문단·서론 ¶2 모순)
14. **조건부 판단은 조건문으로 쓴다** (지름길: "구성 차이가 맞다면")
15. **원인 설명은 대조군으로 검증한다** (A의 암기 원인이 깊이가 아니라 분할 조건 — B와 비교 / B의 보수성 원인이 학습 데이터일 수 없음 — 같은 데이터로 학습한 모델과 비교)
16. **사전 명세의 결정과 원고가 충돌하지 않는지 확인한다** (프로토콜은 상관 측정을 하지 않기로 했는데 원고는 상관을 사실처럼 씀)

### D. 반영 절차
17. **승인 문구는 표에서 그대로 읽어 적용한다.** 다시 타이핑하지 않는다
18. **점검 순서**: 대상 문장 1회 존재 → 새 버전에 적용 → 제거 대상 0건·새 문구 1회 → 용어·공백·부호·접속사 중복 → 인용이 확인 목록 안인지 → **수정 문단과 그 해석이 닿는 곳을 문맥과 함께 재독**
19. **점검 도구가 걸리면 원인부터 확인한다** — 진짜 문제인지 오탐인지 (#12-1: 검색어가 다른 파일의 정상 인용까지 잡음)
20. **"기록하겠다"고 한 것은 그 자리에서 기록한다** (#10 기록 누락)

**⚠️ 표현 원칙 — "사전등록" 사용 금지**
- 사전등록(preregistration)은 OSF·AsPredicted 등 **공개 저장소에 타임스탬프로 등록**해 제3자가 검증 가능한 것을 뜻함

- **공개 등록이 아님을 한계로 명시**하고, 변경이력 전문을 부록 A로 공개

- **오류 2**: A·C·선택적도 **같은 균형 데이터**로 학습. 균형 데이터가 원인이면 B만 보수적일 이유가 없음
- **정정**: 원인은 B의 **하이퍼파라미터**(트리 54, max_features 2, min_samples_split 11 등). 어느 설정인지는 **분리하지 않았음**을 명시
- 프로토콜 v3.5 §13.2의 동일 서술은 사용자 방침에 따라 수정하지 않으나, **논문에서는 반복하지 않음**. 부록 A 공개 시 불일치 가능성 인지

**작성 중 잡은 오류**
- B의 악성 평균확률 "여섯 모델 중 최저" → **D(0.6480)가 더 낮음**. "RF 계열 중 최저"로 범위 정정
- "둘 다 사실과 다르다" → 과도. B의 탐지율 최저는 사실이고 일괄의 AUC도 소폭 상승. "탐지율이 실제로 보여주는 것을 넘어선 해석"으로

**서술 원칙 적용 확인** — 현상 중심(ⓑ): "처음에 이렇게 해석했다"가 아니라 "탐지율만 보면 이렇게 읽힌다"로 서술. 연구자의 해석 정정 경위는 6장·부록으로
